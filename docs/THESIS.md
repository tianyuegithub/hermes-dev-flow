## 一、Thesis（我们赌的是什么）

**AI 编码的瓶颈，不是模型不够聪明，而是交付物无法被问责。**

今天的 AI 编码工具都在卷"让模型更聪明"：更长的上下文、更多的模式、更强的编排。但一个团队敢不敢把代码合并进 main，从来不取决于写代码的人聪不聪明——取决于**交付物能不能被客观地验证、出了问题能不能被追责、验收标准能不能在动手之前就说清楚**。

PactFlow 赌的是：当模型能力趋同、价格趋零时，**契约（Pact）成为 AI 编码基础设施里唯一稀缺的层**。

所以 PactFlow 不是又一个 agent 编排器。它是：

> **AI 编码交付物的契约层。**
> 任务以契约开始（输入契约），以契约验收（输出契约 + 强制校验），以契约升级（逃生舱契约）。编排、路由、评分、容器——都是为契约服务的可替换零件。

## 二、三条推论（架构的第一性原理）

1. **契约必须可执行，否则不存在。**
   写在 JSON 文件里却没有强制校验的"契约"是文档，不是契约。任何未被机器强制的 PactFlow 特性，都不算完成。
   → *当前状态：✅ 2026-07-30 完成。三份契约已强制：intake 入口校验 input，scorecard 闸门 0 校验 output（违反即 auto_reject，无分可赦），技能层（dev-gate 第零步 / dev-run-worker 流转前）双重卡点。见 validate_contract.py。*

2. **证据必须来自外部，不接受自报。**
   Agent 自己声明"我做完了"不计分。只有外部可验证信号（构建通过、测试 green、schema 校验通过、diff 落在声明范围内）才算证据。评分、闸门、择优，全部建立在签名证据链上。
   → *当前状态：✅ 2026-07-30 完成。Scorecard 已重构为外部证据计分：test_result=pass 30 分、commit 25、diff 15、files_changed 10；self_check 零分仅作参考；test_result=fail 一票否决。见 scorecard.py 与 tests/test_contracts.py（27 项测试）。*

3. **人是裁决者，不是执行者；AI 只在契约允许的岔口打扰人。**
   自动化的边界由契约划定：证据齐全 → 自动通过；证据不足 → 携带结构化证据升级到人；严重不达标 → 自动打回。人的每一次介入都被记录（gate_history），并成为优化自动化边界的输入。
   → *当前状态：✅ 2026-07-30 完成。gates.py 已重构为统一闸门：Scorecard 自动裁决为主，dev/test/PM 降级为 escalate 区间内的三级人工角色（顺序裁决、越序报错、任一打回即终止）；所有裁决记入 gate_history 可审计；integrate_hooks 在触发云效前强制消费闸门裁决（此前结果被丢弃）。见 gates.py / integrate_hooks.py / tests/test_gates.py。*

## 三、我们是谁 / 不是谁

| | PactFlow | Paseo | HomeRail |
|---|---|---|---|
| 赌的是 | **契约问责** | 编排模式 | 打分制流程 |
| 交付物 | 带证据链、可被机器审计的 PR | 编排过程 | 打分结果 |
| 验收权 | 契约 + 外部证据 + 人的裁决 | Verifier 循环 | Scorecard |
| 许可证 | MIT（商业友好） | AGPL-3.0 | MIT |

**PactFlow 不做的事（非目标）：**

- 不做 agent 本身。Claude Code / Codex / OpenCode 都是黑盒，可替换。
- 不卷编排模式数量。DAG、路由表够用即可，不为对标加功能。
- 不绑定特定模型供应商。路由表的存在就是为了供应商可替换。
- 不在契约强制化完成之前追求 star 数和外部推广。

## 四、给谁用（楔子市场）

**第一批用户：使用 Claude Code 等 CLI agent、需要把 AI 产出安全合入真实仓库的中文开发者与小团队。**

理由：这块市场对"AI 写完了但我不敢合"的痛最真实；Paseo 等国际项目不服务中文生态（Gitea / 云效 / 国产模型路由）；MIT 许可证让商业团队敢用。

国际推广是契约层成为事实标准之后的自然结果，不是当前目标。

## 五、北极星指标

> **被自动验收的 PR 中，事后被人推翻的比例（false-green rate）。**

这个指标趋近于 0，证明契约有效；它每降一点，用户就敢把更大的任务交给系统。次级指标：

- 人工介入率（escalate 比例）：越低越好，但不能以牺牲 false-green 为代价。
- 单 PR 全链路成本与时间。
- 契约校验拦截次数：证明契约在干活的直接证据。

## 六、决策宪法（给未来的维护者，包括 AI）

每做一个架构决策，按顺序问四个问题：

1. 它让契约**更可强制执行**了吗？（最重要）
2. 它让证据**更来自外部**了吗？
3. 它让人**更少做可自动化的裁决**了吗？
4. 它让核心回路**更诚实**了吗（宁可报失败，不许假绿）？

四问皆否的功能，不做。与四问冲突的已有功能，删。

**诚实条款**：README、SUMMARY、对比表中的每一项宣称，必须能指向一段可运行、可验证的代码或测试。指向不了的，标注 `experimental` 或删除宣称。完成度按"能跑通"计，不按"文件存在"计。
