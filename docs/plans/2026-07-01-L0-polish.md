# L0 打磨计划 · 2026-07-01

> 目标：把 L0 从"能跑"磨到"顺手"。修 6 个毛刺，每个可独立验证。

## 毛刺清单（按依赖排序）

### 1. ✅ intake.py stdout 噪音 — P0

**症状**：
```
state.py init → 打印 {"status":"ok"} 到 stdout
state.py set  → 又打印 {"status":"ok"}
intake.py create → 自己的 JSON 被 subprocess stdout 淹没
调用方 tail -1 拿不到正确的 task_id
```

**根因**：intake.py 调 subprocess.run()，state.py 的 stdout 直接透传。

**修法**：state.py 加 `--quiet` 模式，或 intake.py 把 subprocess stdout 重定向到 stderr/DEVNULL。

**验证**：`TASK_ID=$(intake.py create ... 2>/dev/null | python3 -c "import json,sys; print(json.load(sys.stdin)['task_id'])")` 一行拿到 task_id。

---

### 2. ✅ worker prompt FORBIDDEN 提取 — P0

**症状**：Step 3 中 FORBIDDEN 拼装报 `SyntaxError: unexpected EOF`，prompt.txt 约束段为空。

**根因**：shell 嵌套引号 + Python 括号不匹配。

**修法**：改用 Python 独立脚本拼 prompt，不走 shell 内联。

**验证**：prompt.txt 约束段有内容。

---

### 3. ✅ 多仓库支持 — P1

**现状**：所有地方硬编码 `ssh://git@192.168.31.7:30022/datavdl/deer-flow.git`。

**修法**：
- `scripts/repos.json` — 仓库注册表
- intake / worker / integrate 统一从注册表读 URL
- 自然语言触发时按关键词匹配：说"deer-flow"→匹配 deer-flow

**新增字段**：
```json
{
  "deer-flow": {
    "url": "ssh://git@192.168.31.7:30022/datavdl/deer-flow.git",
    "gitea_repo": "datavdl/deer-flow",
    "language": "python",
    "triggers": ["deer-flow", "deerflow", "灵境"]
  }
}
```

**验证**：说"灵境加一个接口"能匹配到 deer-flow。

---

### 4. ✅ 工作副本隔离 — P1

**症状**：所有任务共用 `worktrees/test-001/repo`，切换分支可能丢未提交改动。

**修法**：
- 用 git worktree 而非分支切换：`git worktree add ../<task_id> origin/main`
- 或简单方案：每个任务独立 clone（首次 74MB，后续 `--reference` 共享对象库）

**选方案**：git worktree — 秒级创建，天然隔离，共享 `.git` 对象库。

**验证**：两个并发任务各有独立 worktree，互不干扰。

---

### 5. ✅ turns 预算 +20% buffer — P2

**现状**：EDIT 6-15 处给 24 turns，实测用了 25（刚好用完，subtype=error_max_turns）。

**修法**：预算表加 20% buffer：
- EDIT 6-15 处：24 → 30 turns
- EDIT 15+ 处：40 → 50 turns

**验证**：同类任务不再 hit max_turns。

---

### 6. ✅ 技能间自动流转 — P2

**现状**：gate 完了要手动说"是"才进 integrate。

**修法**：不追求全自动（那是 L1 reconciler 的事），但加一个"一键到底"模式：
- 用户说"全自动"→ intake → worker → gate（仅验证闸门等人）→ integrate
- 默认保持现状（每步等人确认）

**验证**：说"全自动：deer-flow 加 XX"→只需在验证闸门处确认一次。

---
