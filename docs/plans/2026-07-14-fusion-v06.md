# Dev-Flow v0.6 融合设计 · 基于 Paseo + HomeRail 对标分析

## 最大发现

Dev-Flow 和 Paseo/HomeRail 不是竞争关系——是**互补的三层**：

```
HomeRail  ──→ 输入层强（语音+DAG拆解+生成式UI）
Dev-Flow  ──→ 质量层强（契约+闸门+容器化执行面）
Paseo     ──→ 控制层强（多厂商路由+跨设备+协议）
```

融合方向：把三家的强项拼成一条完整链路。

## 融合架构

```
语音输入 (HomeRail模式)
    │
    ▼
意图收集 + DAG拆解 ────→ 编排偏好路由 (Paseo模式)
    │                        │
    │              ┌─────────┼─────────┐
    ▼              ▼         ▼         ▼
  Node 1        Claude    Codex    OpenCode
  Node 2         │         │         │
  Node 3    ←────┴─────────┴─────────┘
    │              产出对比 (Scorecard)
    ▼
  Gate (六项→Scorecard自动化)
    │
    ▼
  PR + Archive (可回放 DAG)
```

## 具体改动（按优先级）

### P0：状态机 DAG 化（今天）
- `state.py` 从 6 态线性 → DAG 节点图
- 每个 node 独立 state.json + workspace
- 支持回放和 diff 对比

### P1：Scorecard 替代人工闸门（本周）
- `scorecard.py`：dimension 打分（有commit=50分，diff完整度=20分，成本=5分，turns=3分，self_check=10分）
- 总分>=70 自动通过，50-70 escalate，<50 打回
- 保留人拍板作为 override

### P2：编排偏好路由表（下周）
- `orchestration-preferences.json`：task_type→provider/model
- 支持 committee 模式（两个 agent 并行→选优）

### P3：Worker 三层架构（后续）
- Manager→Node→Worker 替代单 Pod 热池
- 保持现有的 Redis 引用传递
