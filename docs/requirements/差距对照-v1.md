## 三、关键差距汇总（按优先级）

| # | 差距 | 说明 | 工作量 |
|---|------|------|--------|
| G1 | **项目空间概念** | worker 按项目归属（1对多），任务按项目分发 | 中 |
| G2 | **按项目 slot 热池** | 每个项目预制 Pod 槽位，复用 | 中 |
| G3 | **my-fusion 评审入口** | intake 自动调「多模型融合评估」skill | 小 |
| G4 | **启动时动态注入凭据** | K3s 管理 Base URL/API Key，Pod 启动注入（init container 或 env-from） | 小 |
| G5 | **release 制品概念** | worker 完成→release→再接任务（制品版本记录） | 中 |
| G6 | **构建缓存/共享环境** | Node/Maven 环境共用（PV 挂载或 pnpm store 共享） | 中 |
| G7 | **Hook 实时通知** | Hermes 主线程实时推送（当前是轮询） | 小 |

## 四、需用户确认的问题

1. **worker↔任务 1对1**：是指"同一时刻一个 worker 只跑一个任务"（现在热池是串行接任务，已满足）？还是要"一个任务绑死一个专属 worker"？
2. **release 是什么形态**：Git tag？制品库？还是只是"完成标记"？
3. **共用 Node 环境**：是只读共享 node_modules（pnpm store 模式）还是完整共享？
4. **模型跑在 K3s Pod 里**：是指模型 API 服务（如 vLLM 部署 DeepSeek 到 K3s）也在 Pod 里？还是只是 CLI agent 在 Pod 里调用外部模型 API？
5. **"多模型融合评估" skill**：是现有 Hermes 的 my-fusion skill 吗？评审的输出是什么格式？
